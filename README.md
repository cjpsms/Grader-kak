# Grader

ระบบตรวจโค้ดอัตโนมัติ (online judge ขนาดเล็ก) สำหรับห้องเรียน/ชมรม เขียนด้วย Node.js + Express
นักเรียนสมัครสมาชิก เลือกโจทย์ เขียนโค้ด **C++17 หรือ Python 3** แล้วส่งตรวจ ระบบคอมไพล์ รันกับเทสต์เคสที่ซ่อนไว้
และบอกผลทีละเทสต์ ผู้ดูแล (admin) สร้าง/แก้โจทย์ เทสต์เคส และกำหนดเวลา/หน่วยความจำต่อโจทย์ได้จากหน้าเว็บ

- หน้าเว็บภาษาไทย ธีมสว่าง/มืด ตัวแก้โค้ด CodeMirror
- ไม่ใช้ฐานข้อมูล เก็บข้อมูลเป็นไฟล์ JSON ใน `data/`
- มีปุ่ม "รันทดลอง" ให้นักเรียนลองใส่ input เอง โดยไม่นับเป็นการส่ง

## โจทย์

โจทย์ที่ใช้ในระบบนี้ เป็น **โจทย์จาก POSN KP 1 และโจทย์อื่นๆ ที่ทำกันเอง** รวม 20 ข้อ อยู่ในโฟลเดอร์ [`problems/`](problems/)
แยกตามโปรเจกต์ (`ex`, `veryEZ`, `anime`) ดูรายการและที่มาได้ที่ [problems/README.md](problems/README.md)
โฟลเดอร์นั้นมีเฉพาะไฟล์โจทย์ (PDF) ไม่มีเทสต์เคสและเฉลย

## ความต้องการของระบบ

| สิ่งที่ต้องมี | หมายเหตุ |
|---|---|
| Node.js | แนะนำ 20 ขึ้นไป (พัฒนาและทดสอบบน 24) โปรเจกต์เป็น ES modules และใช้ top-level `await` |
| `g++` (รองรับ C++17) | ต้องอยู่ใน `PATH` บน Windows ใช้ MSYS2 (ucrt64) ได้ |
| `python` / `python3` | Python 3 ต้องอยู่ใน `PATH` (Windows เรียก `python`, Linux เรียก `python3`) |
| อินเทอร์เน็ตฝั่งผู้ใช้ | หน้าเว็บโหลด Tailwind, CodeMirror และฟอนต์จาก CDN ถ้าโหลดตัวแก้โค้ดไม่ได้ภายใน 8 วินาที จะใช้ช่องกรอกข้อความธรรมดาแทน |
| **Windows:** .NET Framework (`csc.exe`) | มากับ Windows อยู่แล้ว ใช้คอมไพล์ตัว sandbox ครั้งแรกที่ server เริ่ม |
| **Linux:** `bash`, (แนะนำ) `firejail` | ดู [ความปลอดภัยและ sandbox](#ความปลอดภัยและ-sandbox) |

## เริ่มใช้งาน

```bash
git clone https://github.com/cjpsms/Grader-kak.git
cd Grader-kak
npm install
npm start
```

เปิด `http://localhost:3000` (ค่าเริ่มต้น) **คนแรกที่สมัครสมาชิกจะได้เป็น admin อัตโนมัติ** ให้สมัครบัญชีของคุณก่อนเปิดให้คนอื่นใช้

เปลี่ยน port บน Windows (PowerShell):

```powershell
$env:PORT = "4500"; npm start
```

> สคริปต์ `npm run dev` ใช้ไวยากรณ์ `NODE_ENV=... node ...` ซึ่งใช้ได้เฉพาะ bash บน Windows ให้ใช้ `npm start`

ครั้งแรกที่เริ่มบน Windows server จะ (1) คอมไพล์ `graders/sandbox_runner.exe` จาก `sandbox_runner.cs` ถ้ายังไม่มี และ
(2) สร้างโฟลเดอร์ `.sandbox/` พร้อมตั้งสิทธิ์ด้วย `icacls` ถ้าสองขั้นนี้ทำไม่สำเร็จ server **จะไม่ยอมเริ่ม** (ไม่ตรวจโค้ดโดยไม่มี sandbox)

## การตั้งค่า

ตั้งผ่าน environment variable

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|

ค่าที่ปรับในโค้ด (ไฟล์ที่เกี่ยวข้อง):

| ค่า | ที่ไหน | ค่าปัจจุบัน |
|---|---|---|
| ตรวจพร้อมกัน | `server.js` (`MAX_CONCURRENCY`) | `min(2, จำนวน CPU)` |
| คิวสูงสุด | `server.js` (`MAX_QUEUE`) | 40 งาน |
| อายุ session | `server.js` (`SESSION_TTL_MS`) | 7 วัน |
| ขีดจำกัดเวลา/หน่วยความจำ | `graders/limits.js` | ดู [เวลาและหน่วยความจำ](#เวลาและหน่วยความจำ) |

## การใช้งาน

### นักเรียน
1. สมัครสมาชิก (รหัสผ่านต้องมีตัวเลขอย่างน้อย 1 ตัว ยาวไม่เกิน 72 ตัวอักษร) แล้วเข้าสู่ระบบ
2. เลือกโปรเจกต์ → เลือกโจทย์ (อ่านโจทย์จาก PDF ในหน้าเดียวกัน)
3. เขียนโค้ด หรือนำเข้าไฟล์ `.cpp` / `.py` แล้วกด **ส่ง** (Ctrl/Cmd + Enter) หรือกด **รัน** เพื่อลองกับ input ของตัวเอง
4. ดูผลทีละเทสต์ และประวัติการส่งทั้งหมดที่เมนู "ซับมิท" แบบร่างของโค้ดถูกเก็บในเบราว์เซอร์ให้อัตโนมัติ

ผู้ใช้หนึ่งคนมีงานที่กำลังตรวจได้ครั้งละ 1 งาน (ส่งซ้อนจะได้ข้อความว่ารอให้เสร็จก่อน)

### Admin (เมนู "จัดการระบบ")
- **โปรเจกต์:** สร้าง เปิด/ปิด ลบ (ลบแล้วโจทย์และซับมิทใต้โปรเจกต์หายไปด้วย) นักเรียนเห็นเฉพาะโปรเจกต์ที่เปิด
- **โจทย์:** สร้างโดยแนบ PDF + เทสต์เคส + เวลา/หน่วยความจำ แก้ภายหลังได้ที่ปุ่ม **แก้ไข** ข้างโจทย์ (ชื่อ, โปรเจกต์, limit, เทสต์เคส, เปลี่ยน PDF) หรือลบ
- **ผู้ใช้:** ให้/ถอนสิทธิ์ admin ลบผู้ใช้ (ลบตัวเอง หรือ admin คนสุดท้ายไม่ได้)
- **ซับมิท:** ดูซับมิททุกคน รวมโค้ด log และ input/expected/got ของทุกเทสต์

ลำดับโจทย์ที่นักเรียนเห็นคือลำดับของโจทย์ในไฟล์ `data/problems.json` โจทย์ใหม่จะต่อท้ายสุด

## เขียนเทสเคส

มี 2 รูปแบบ ในหน้าเว็บมีคำอธิบายแบบละเอียดให้กางดูทั้งสองที่

### 1) ตอนสร้างโจทย์: บรรทัดละ 1 เคส `input => expected`

```
1 2 => 3
3\n10\n20\n30 => 60
3\n3 1 2 => 1\n2\n3
hello world => HELLO WORLD
```

- ซ้ายคือข้อมูลที่ป้อนเข้า stdin ขวาคือ output ที่ถูกต้อง บรรทัดว่างถูกข้าม
- ใช้ `\n` แทนการขึ้นบรรทัดใหม่ (เคสที่ 2 ป้อน 4 บรรทัด คือ 3, 10, 20, 30)
- ต้องการเครื่องหมาย `\` จริงๆ ให้พิมพ์ `\\` (`a\\nb` = ตัวอักษร a `\` n b ไม่ขึ้นบรรทัดใหม่)
- ว่างเปล่าได้: `=> x` (ไม่มี input), `5 =>` (ไม่มี output)
- ใช้ `=>` ได้ครั้งเดียวต่อบรรทัด (ตัวหลังถูกตัดทิ้ง)

### 2) ตอนแก้โจทย์: บล็อก `@@ input` / `@@ expected`

```
@@ input
3
10
20
30
@@ expected
60

@@ input
1 2
@@ expected
3
```

ขึ้นบรรทัดใหม่จริงได้ ไม่มีการแปลงตัวอักษรพิเศษ ใส่ `=>` ในข้อความได้ ข้อจำกัด 1–5000 เคส
และแต่ละ input/expected ไม่เกิน 100,000 ตัวอักษร ต้องมีอย่างน้อย 1 เคส

### การเทียบคำตอบ
- CRLF ถือว่าเท่ากับ LF
- ตัดช่องว่าง/บรรทัดว่างที่ **หัวและท้ายของ output ทั้งก้อน** ก่อนเทียบ
- ช่องว่างระหว่างคำและท้ายแต่ละบรรทัด **ต้องตรงเป๊ะ** (`1 2` ไม่เท่ากับ `1  2`)

### แก้เทสเคสแล้วคะแนนเก่าเป็นอย่างไร
เมื่อชุดเทสต์เปลี่ยนจริง โจทย์จะมี `testsRev` เพิ่มขึ้น ซับมิทเก่ายังอยู่ในประวัติ ขึ้นป้าย **"เทสต์ชุดเดิม"**
แต่ **ไม่นับ** ในคะแนนดีที่สุด/จำนวนข้อที่ผ่าน และตัวหารที่แสดงเป็นจำนวนเทสต์ปัจจุบัน นักเรียนต้องส่งใหม่
(แก้แค่ชื่อ/เวลา/หน่วยความจำ หรือบันทึกเทสต์เดิมซ้ำ ไม่ทำให้ `testsRev` เพิ่ม)

## เวลาและหน่วยความจำ

ตั้งต่อโจทย์ได้ตอนสร้างและตอนแก้

| | ต่ำสุด | สูงสุด | ค่าเริ่มต้น |
|---|---|---|---|
| เวลาต่อ 1 เทสต์ | 100 ms | 10,000 ms | 2,000 ms |
| หน่วยความจำต่อโปรเซส | 16 MB | 1,024 MB | 256 MB |

- โจทย์เก่าที่ยังไม่มีค่านี้ใช้ค่าเริ่มต้นให้อัตโนมัติ
- ปุ่ม "รัน" ที่ส่ง `problemId` มาด้วยจะใช้ limit ของโจทย์นั้น (ลองแล้วได้ผลเหมือนตอนตรวจจริง)
- ขั้นคอมไพล์ C++ มีเพดานแยก: 20 วินาที / 2 GB / 8 โปรเซส
- output ของโปรแกรมต่อเทสต์ถูกจำกัดที่ 1 MB และเก็บลงผลซับมิทแค่ 2,000 ตัวอักษรแรกต่อเทสต์ (ตัดสินถูกผิดด้วย output เต็มก่อนตัด)
- งานหนึ่งครั้งมีงบเวลารวม = 20 วินาที + จำนวนเทสต์ × (limit + 0.7 วินาที) สูงสุด 5 นาที ถ้าเกินจะหยุดเปิดเทสต์ถัดไป

## ความปลอดภัยและ sandbox

โค้ดนักเรียนคือโค้ดที่ไม่น่าไว้ใจ ระบบป้องกันเป็นชั้นๆ:

1. **สแกนก่อนรัน** (`security/policy.js`) ปฏิเสธโค้ดที่ใช้ API ต้องห้าม เช่น `system`, `fork`, `CreateProcess`, `<windows.h>`,
   `#include` ไฟล์ด้วย path (C++) หรือ `import os/subprocess/socket/ctypes...`, `__import__`, `eval`, `open(` (Python)
   นี่เป็นด่านแรกที่ **หลบได้** ไม่ใช่ขอบเขตความปลอดภัยจริง
2. **sandbox ตอนรัน**
   - **Windows:** ตัวคอมไพเลอร์และโปรแกรมของนักเรียนรันผ่าน `graders/sandbox_runner.exe` ซึ่งให้
     restricted token + Low integrity (อ่านโฟลเดอร์ข้อมูลของ user/`data/` ไม่ได้ เขียนนอกโฟลเดอร์ scratch ไม่ได้),
     Job Object จำกัดหน่วยความจำและจำนวนโปรเซส (สร้างโปรเซสลูก/เปิด shell ไม่ได้) และ timeout
     แต่ละงานรันใน `.sandbox/grader-<uuid>/` แล้วลบทิ้ง
   - **Linux:** ใช้ `ulimit` (CPU, RAM, ไฟล์, fd) + `timeout` และ `firejail --net=none --private` ถ้าเครื่องมี firejail
3. **จำกัดการใช้ทรัพยากร:** จำกัดคนตรวจพร้อมกัน, 1 งานต่อผู้ใช้, คิวสูงสุด 40, rate limit 5 คำขอ/วินาที/IP

ฝั่งเว็บ: รหัสผ่านเก็บแบบ bcrypt, session secret สุ่ม, session เก็บเป็นไฟล์ (`httpOnly`, `sameSite=lax`), ล็อกอินผิดเกิน 10 ครั้งต่อ 15 นาที/IP จะถูกล็อก,
ตรวจ `Origin` กัน CSRF, สิทธิ์ของผู้ใช้ถูกตรวจใหม่ทุก request, helmet, และผู้ดูแลคนสุดท้ายลบหรือถอนสิทธิ์ไม่ได้

### ข้อควรระวัง
- **Windows ไม่มีการตัด network ของโค้ดนักเรียน** (ทำไม่ได้โดยไม่ใช้สิทธิ์ admin) ถ้าต้องการแยกขาด ให้รันบน Linux + firejail/Docker
- ฝั่ง Linux ของโปรเจกต์นี้ **ยังไม่ได้ทดสอบ** (ผู้พัฒนาใช้ Windows) ให้ทดสอบกับโจทย์จริงก่อนใช้งาน
- server พูด HTTP ธรรมดา (cookie ไม่ตั้ง `secure`) ถ้าเปิดสู่อินเทอร์เน็ต ควรวางหลัง reverse proxy ที่ทำ HTTPS
- ไม่มีการยืนยันอีเมล/ป้องกันการสมัครสแปมนอกจาก rate limit ถ้าเปิดสาธารณะ ควรเพิ่มมาตรการเอง

## โครงสร้างโปรเจกต์

```

  build_runner.ps1        สคริปต์คอมไพล์ sandbox_runner.exe ด้วย csc.exe
security/policy.js        รายการ API ต้องห้าม + ตัวสแกน + ค่า ulimit/firejail (Linux)
utils/storage.js          อ่าน/เขียน JSON แบบมี lock และเขียนไฟล์แบบอะตอมมิก
public/                   หน้าเว็บ (index.html, app.js)
problems/                 ไฟล์โจทย์ (PDF) ที่เผยแพร่ แยกตามโปรเจกต์ + README บอกที่มา (ไม่มีเทสต์เคส)
data/                     ข้อมูลระบบ (สร้างเอง, ไม่อยู่ใน git)
uploads/pdfs/             ไฟล์ PDF โจทย์ (สร้างเอง, ไม่อยู่ใน git)
.sandbox/                 โฟลเดอร์ชั่วคราวของแต่ละการรัน (Windows, สร้างเอง)
```

| `data/users.json` | ผู้ใช้ (รหัสผ่านเป็น bcrypt hash) และสิทธิ์ admin |
| `data/projects.json` | โปรเจกต์ |
| `data/problems.json` | โจทย์ + เทสเคสทั้งหมด (**ห้ามให้นักเรียนเข้าถึง**) |
| `data/submissions.json` | ซับมิททุกครั้ง (โค้ด ผลทีละเทสต์) |
| `data/sessions/` | session ที่ล็อกอินอยู่ |
| `data/session-secret.txt` | ความลับของ session |
| `uploads/pdfs/` | PDF โจทย์ |

สำรอง: ก๊อป `data/` และ `uploads/` ทั้งโฟลเดอร์ (ปิด server ก่อนจะปลอดภัยที่สุด) การย้ายเครื่องก็แค่ก๊อปสองโฟลเดอร์นี้ไปไว้ข้างโค้ด
อย่า commit โฟลเดอร์เหล่านี้ขึ้น git (`.gitignore` กันไว้แล้ว เพราะมี hash รหัสผ่านและโค้ดของนักเรียนทุกคน)

## API

ตอบเป็น JSON รูปแบบ `{ ok: true, ... }` หรือ `{ ok: false, error: "..." }` ต้อง login (cookie) ยกเว้นที่ระบุ

| Method | Path | สิทธิ์ | หน้าที่ |
|---|---|---|---|
| POST | `/api/register`, `/api/login` | ไม่ต้อง login | สมัคร / เข้าสู่ระบบ |
| POST | `/api/logout` | — | ออกจากระบบ |
| GET | `/api/me` | — | ผู้ใช้ปัจจุบัน (`null` ถ้ายังไม่ login) |
| GET | `/api/projects` | ผู้ใช้ | รายการโปรเจกต์ |
| GET | `/api/problems`, `/api/problems/byProject?projectId=` | ผู้ใช้ | โจทย์ของโปรเจกต์ที่เปิด (ไม่มีเทสต์เคส มีแค่ `testCount`, limit, `testsRev`) |
| POST | `/api/run` | ผู้ใช้ | รันโค้ดกับ input ที่ระบุ (`language`, `code`, `input`, `problemId?`) |
| POST | `/api/submit` | ผู้ใช้ | ส่งตรวจ (`problemId`, `language`, `code`) |
| GET | `/api/my/submissions` | ผู้ใช้ | ซับมิทของฉัน |
| GET | `/api/admin/users`, `/api/admin/problems`, `/api/admin/submissions` | admin | ข้อมูลทั้งหมด (โจทย์มีเทสต์เคสเต็ม) |
| POST | `/api/admin/users/grant`, `/api/admin/users/delete` | admin | จัดการผู้ใช้ |
| POST | `/api/admin/projects/create`, `/toggle`, `/delete` | admin | จัดการโปรเจกต์ |
| POST | `/api/admin/problems/create` | admin | สร้างโจทย์ (`multipart/form-data`: `title`, `projectId`, `testsText`, `timeLimitMs`, `memLimitMB`, `pdf`) |
| POST | `/api/admin/problems/update` | admin | แก้โจทย์ (JSON: `id` + ฟิลด์ที่ต้องการเปลี่ยน `title`, `projectId`, `timeLimitMs`, `memLimitMB`, `tests`) |
| POST | `/api/admin/problems/pdf` | admin | เปลี่ยน PDF (`multipart/form-data`: `id`, `pdf`) |
| POST | `/api/admin/problems/delete` | admin | ลบโจทย์พร้อมซับมิท |

## แก้ปัญหา

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| server ไม่ยอมเริ่ม มีข้อความ `cannot set up the code sandbox` | Windows: ไม่พบ `csc.exe` หรือตั้งสิทธิ์ `.sandbox` ไม่สำเร็จ ดูข้อความต่อท้ายใน log |
| `spawn ... ENOENT` ตอนตรวจ | path ของโปรเจกต์ยาวเกิน 260 ตัวอักษรบน Windows ให้ย้ายโปรเจกต์ไปไว้ path ที่สั้นกว่านี้ หรือเช็กว่า `g++`/`python` อยู่ใน `PATH` ของ process ที่รัน server |
| คอมไพล์ไม่ผ่านทุกข้อ | `g++` ไม่อยู่ใน `PATH` ของ process ที่รัน server (ลอง `g++ --version` ในหน้าต่างเดียวกัน) |
| `EADDRINUSE` | port ถูกใช้แล้ว เปลี่ยน `PORT` หรือปิดโปรเซสเดิม |
| โจทย์ไม่ผ่านทั้งที่ output เหมือน | ดูช่องว่างท้ายบรรทัด/ระหว่างคำ และ `\n` ในเทสเคส ([เขียนเทสเคส](#เขียนเทสเคส)) |
| ผลที่นักเรียนส่งไว้หายไปจากคะแนน | แอดมินแก้เทสเคสหลังจากส่ง ดู [แก้เทสเคสแล้วคะแนนเก่าเป็นอย่างไร](#แก้เทสเคสแล้วคะแนนเก่าเป็นอย่างไร) |
| server ปิดเองและมี `heap out of memory` ใน log | ควรไม่เกิดแล้วจากการจำกัด output ถ้าเกิด ให้เก็บ log ไว้ดูว่ากำลังตรวจโจทย์ไหน |

## ข้อจำกัดที่ควรรู้
- ตรวจได้เฉพาะ C++17 และ Python 3 โจทย์แบบ special judge / interactive ยังไม่รองรับ (เทียบ output แบบตรงทุกตัวอักษรหลังตัดช่องว่างหัวท้าย)
- แต่ละเทสต์เปิดโปรเซสใหม่ โจทย์ที่มีเทสต์ ~1,000 เคสใช้เวลาตรวจราว 45 วินาที
- หน้า admin โหลดซับมิททั้งหมดในครั้งเดียว ยิ่งข้อมูลโต ยิ่งช้า (ยังไม่มีการแบ่งหน้า)
- การจัดลำดับโจทย์ต้องแก้ลำดับในไฟล์ `data/problems.json` เอง (ยังไม่มีปุ่มเลื่อนในหน้าเว็บ)
- ยังไม่มีชุดทดสอบอัตโนมัติใน repo
